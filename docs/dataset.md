# Dataset

## Source

Experiments use the **Cyber-Physical Anomaly Detection in Smart Homes** dataset, introduced by Yasar Majib, Mohammed Alosaimi, Andre Asaturyan, and Charith Perera (*Frontiers in the Internet of Things*, 2023, DOI: 10.3389/friot.2023.1275080).

The dataset combines network traffic, smart-device, and environmental sensor data collected in a smart-home environment over approximately four weeks, covering two actors: a primary actor representing normal activity, and a second actor introduced for a shorter period, usable for anomalous-behaviour analysis. It includes both raw and processed representations of each source, and a merged timeline intended for cyber-physical analysis.

The dataset is **publicly available through the repository associated with the original publication** and is **not redistributed** in this project. It must be obtained and prepared separately before running the pipeline.

## Data Preparation and Missing Cyber Data

The original dataset provides raw and processed representations of each data source. During preparation for this project, missing portions were identified in the available cyber master data. The corresponding raw cyber files were located, inspected, and used to recover the required records, which were then converted and merged using the corresponding master-data structure and field format.

This step was necessary to obtain a consistent cyber representation for synchronization with the physical and device data.

The original cyber dataset is based on hourly packet-capture (`.pcap`) files. Per the original documentation, these are converted to CSV, timestamped, joined, and normalized. The physical dataset also has documented capture-related issues; the original processing includes cleaning and repairing affected sensor values.

## Data Used in the Implementation

### Physical Data

```text
SensorDataMasterTransposed.csv
```

This master representation is used as the physical-data input for preprocessing and subsequent feature extraction.

### Device Data

```text
BREMaster.csv
CUMaster.csv
```

These master files are used as the device-data inputs for preprocessing and synchronization. The combined device master data is approximately 3.82 GB.

### Cyber Data

```text
CyberMasterNormalisedNoInfo.csv
```

The cyber modality uses the cyber master representation together with the corresponding raw PCAP files. The raw packet captures were inspected and used where required to address missing records in the cyber master data before generating the final cyber representation.

Packet-level fields include frame number, timestamp, source, destination, protocol, packet length, and packet information; these are transformed into the feature representation used by the cyber encoder.

### Supporting Metadata

The following metadata files are used to support the preparation, mapping, and synchronization of the three modalities:

```text
ActivityLabels.json
ActivityLogR1.csv
ActivityLogR2.csv

BRE_CyPhyDevices.json
BRE_Devices_Location_Sensors.json

CU_CyPhyDevices.json
CUStatesMap.json

CyberDevices.json
PIDMap.json
ProtocolMap.json

SmartDevices_Data_and_Frequency.csv
```

These provide activity information, device mappings, and protocol mappings required to interpret and synchronize the source data.

## Modality Feature Dimensions

The final synchronized multimodal dataset contains 40,802 observations:

```text
Physical features : 572
Device features   : 2,780
Cyber features    : 12
```

## Generated Data (Not Committed)

The preprocessing pipeline (`scripts/`) generates synchronized feature files:

```text
Xp_common.csv
Xd_common.csv
Xc_common.csv
```

And compact embeddings used by the fusion model:

```text
Cp, Cd, Cy, CS
```

The federated experiment (`experiments/`) additionally requires:

```text
client_1.pkl
client_2.pkl
client_3.pkl

Cp_test.pkl
Cd_test.pkl
Cy_test.pkl
CS_test.pkl

TestLabels.csv
```

None of these generated files, nor trained model checkpoints, are committed to version control — they must be regenerated by running the `scripts/` pipeline against a locally prepared copy of the source dataset.

## Evaluation Protocol

The synchronized dataset (40,802 observations) is split 80:20:

```text
Training observations  : 32,641
Evaluation observations: 8,161
```

Evaluation set composition:

```text
Normal observations    : 7,297
Anomalous observations : 864   (~10.6%)
```

Every evaluation observation receives a reconstruction-error anomaly score from the trained global model. See [`experiments.md`](experiments.md) for how thresholds and metrics are derived from these scores.
